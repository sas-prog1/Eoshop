## الهدف

إكمال تجربة الشراء المرئية لقالب Elegant بدءًا بسلة تسوق تحريرية واضحة ثم صفحة إتمام طلب تحمل الهوية نفسها، مع إبقاء الكتالوج والأسعار والمخزون والشحن والدفع وإنشاء الطلب خاضعة للمصادر والمنطق الخادمي الحالي.

## تسلسل التنفيذ

1. T1 — فصل واجهة سلة Elegant وتحسين بنيتها البصرية وحالاتها والكمية والمجموع دون تغيير منطق السلة.
2. نقطة اعتماد بصري لسطح المكتب والجوال.
3. T2 — فصل واجهة إتمام الطلب في Elegant مع إعادة استخدام حسابات الطلب والتحقق والإرسال الحاليين.
4. اختبارات مركزة ثم مجموعة Frontend الكاملة والبناء ومراجعة عدم تأثر Tech.

## داخل النطاق

- تركيب بصري مستقل لسلة Elegant وحالات الفراغ والنجاح والمنتجات.
- المحافظة على حجز التركيز، الإغلاق بلوحة المفاتيح، الاستجابة، والحركة المخفّضة.
- عرض السعر والكمية والمجموع والعملة من الحالة الحالية فقط.
- المحافظة على حدود المخزون الحالية ومنع تجاوز الكمية المتاحة.
- صفحة إتمام طلب Elegant في T2 دون إنشاء مسار تجارة جديد.

## خارج النطاق

- لا تغيير API أو قاعدة بيانات أو عقود الطلب والدفع.
- لا تغيير قالب Tech أو سلوكه أو تركيبه.
- لا إضافة دفع حقيقي أو مراجعات أو قائمة أمنيات أو وعود شحن غير منشورة.
- لا Merge قبل اعتماد المالك للدليل البصري وإغلاق البوابات.

## معايير القبول لـT1

- السلة تحمل هوية Elegant بوضوح على سطح المكتب والجوال.
- فتح السلة وإغلاقها وحجز التركيز واستعادته تعمل كما كانت.
- زيادة الكمية وتقليلها وحد المخزون والانتقال لإتمام الطلب تعمل بالمنطق المشترك الحالي.
- حالة السلة الفارغة وحالة إرسال الطلب صادقتان ولا تحتويان وصفًا تجريبيًا مضللًا.
- اختبارات السلة المركزة واختبارات الوصول والانحدار ذات الصلة ناجحة.
- دليل بصري محفوظ داخل `reports/wp-5.27.2d/` قبل بدء T2.
